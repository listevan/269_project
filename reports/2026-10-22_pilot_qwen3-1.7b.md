# Token replay pilot: results of the 2026-10-22 run

Student `Qwen/Qwen3-1.7B`, teacher `Qwen/Qwen3-4B`, MATH-500 levels 3,4,5, run folder `runs/2026-10-22_qwen3-1.7b/`.
The design, the measures and the gates are defined in the notebook's first cell and in the proposal; this file reports
what came out. Every number below is copied from the run's tables, kept in `reports/2026-10-22_pilot_qwen3-1.7b_tables/`.

## Summary

All four wiring gates pass and the signal gate is detected. **The tokens OPSA would push down are less useful than
tokens drawn at random from the same answers**: usefulness U(OPSA) − U(random) = -0.096 [-0.174, -0.019],
bootstrap p = 0.014 with problems resampled. OPSA's own tokens are neutral on average
(U = -0.027 [-0.075, +0.011]): replacing one of them neither helps nor hurts the chance of a correct answer in a way this
sample can see. Still, **25% of OPSA's tokens are useful** (keeping the token beats redistributing its probability) and
33% are harmful. A random token from the same answers is useful on average (U = +0.068 [+0.008, +0.128]),
mostly because of tokens in correct answers. Teacher-negative selection behaves like OPSA (58% of OPSA's tokens
are also teacher-negative tokens); NSR's set, every token of a failed answer, is neutral.

Weighted by how far a unit push can move the token (damage D = p(1−p)U), OPSA's tokens point the same way,
D = -0.0053 [-0.0132, +0.0007], but the interval touches zero. Random tokens sit at p ≈ 1, so a push barely
moves them and their damage is ≈ 0 by construction; OPSA's tokens sit at p ≈ 0.505, where a push has leverage.

So for the proposal's question: in this pilot, OPSA's penalized set holds a smaller share of useful tokens than a random
set would (25% vs 42%), and its mean effect is not harmful, but one token in four that it pushes down is one the
model was right to produce. The sample is small (64 positions per rule from about 20 problems); the next step is a larger run.

## Replay noise

| positions with a second kept pass | mean \|Q_kept - Q_dup\| | expected from sampling alone | corr(Q_kept, Q_dup) | sign of U agrees |
|---|---|---|---|---|
| 73 | 0.104 | 0.106 | 0.88 | 0.64 |

Two independent kept passes at the same positions differ by about what 8 binomial draws predict, so the replay
adds no noise of its own. But the sign of a single position's U agrees between passes only 64% of the time:
**per-token usefulness is noisy at 8 + 8 continuations**, and the conclusions above are about means over positions,
not about individual tokens. The examples below are illustrations, not evidence.

## Caveats

- **Size.** 64 positions per rule from 18 to 23 problems, 8 + 8 continuations each. The intervals are wide; the pilot
  was sized to see large gaps only, and it saw one between OPSA and random.
- **Per-token noise.** With 8 continuations a side, a single U is a coarse estimate (sign agreement between kept passes
  64%). "share U>0" counts positions whose noisy U came out positive; part of that share is chance.
- **Local measure.** U and D look at one position with the rest of the answer resampled from the same model. They say
  nothing about how a training update at one token changes behaviour elsewhere through the shared weights.
- **Mixed problems only.** Positions were drawn from problems the model sometimes solves. On always-solved or
  never-solved problems a token's effect is pinned near 0 and could not show anyway.
- **Software.** vLLM's nightly ROCm build; gate 1 confirms its log-probabilities match transformers'.

## Next steps

The notebook's rule: if gates 0 to 3 pass, run larger and run the released OPSA checkpoint.

1. More positions per rule (256 or more) and more continuations per position (16 + 16) to tighten the intervals and
   make per-token signs meaningful; the run takes about 35 minutes at this size on the RX 9070 XT, so a 4× run is an
   afternoon.
2. The same replay on `Tuwhy/Qwen3-1.7B-OPSA`: does training on these tokens change which tokens the rule picks and
   how useful they are?
3. MBPP+ (needs sandboxed test runs for grading).
4. Within OPSA's set, split by probability band and by token type to see where the useful quarter lives.
